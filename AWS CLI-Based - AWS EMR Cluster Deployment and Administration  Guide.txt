🎯 Introduction - Amazon EMR on EC2 Deployment Using AWS CLI: End-to-End Cluster Provisioning, Validation, and Node Verification Guide.
-----------------------------------------------------------------------------------------------------------------------------------------

This document demonstrates the complete deployment and validation of an Amazon EMR (Elastic MapReduce) cluster on AWS using 
the AWS Command Line Interface (CLI). The objective of this exercise is to provision a fully functional EMR environment, 
validate all prerequisite AWS resources, create the cluster through automation, 
and verify the successful operation of the Primary, Core, and Task nodes.

The implementation covers validation of AWS authentication, IAM roles, instance profiles, EC2 key pairs, networking components, and security groups 
before cluster deployment. A reusable shell script is then created to automate EMR cluster provisioning with Hadoop, Spark, Hive, HBase, 
and Livy applications. After deployment, the cluster status, node configuration, EC2 instances, networking details, 
and operational readiness are verified using AWS CLI commands.

This document serves as a practical reference for cloud engineers, database administrators, and big data administrators 
who want to understand and implement Amazon EMR cluster deployment, infrastructure validation, cluster monitoring, and node identification entirely 
through command-line automation.

🎯 Project Objectives
👉 Validate AWS account access and CLI authentication.
👉 Verify EMR Service Role and EC2 Instance Profile configurations.
👉 Confirm availability of Key Pairs, Subnet, and Security Groups.v
👉 Create a reusable AWS CLI deployment script.
👉 Deploy an Amazon EMR cluster with Hadoop, Spark, Hive, HBase, and Livy.
👉 Verify cluster creation and operational status.
👉 Identify and validate Primary, Core, and Task nodes.
👉 Retrieve cluster and instance details.
👉 Monitor cluster lifecycle and health.
👉 Demonstrate complete EMR administration using AWS CLI automation

Task 7 - Create EMR Cluster Creation Script ✅
---------------------------------------------
🟢 Purpose : Create a reusable shell script for cluster deployment.
👉 Command : cat > emr-create.sh

~ $ cat > emr-create.sh
aws emr create-cluster \
 --name "EMR-Hadoop-Spark-Cluster" \
 --log-uri "s3://aws-logs-242901278433-us-east-1/elasticmapreduce" \
 --release-label "emr-6.8.0" \
 --service-role "arn:aws:iam::242901278433:role/service-role/AmazonEMR-ServiceRole-20261110T222717" \
 --ec2-attributes '{"InstanceProfile":"AmazonEMR-InstanceProfile-20261110T222658","EmrManagedMasterSecurityGroup":"sg-0a4e45d14aed4215e","EmrManagedSlaveSecurityGroup":"sg-058282bd2b2287271","KeyName":"KP3-ASG","AdditionalMasterSecurityGroups":["sg-0deb3931b70dac7d0"],"AdditionalSlaveSecurityGroups":[],"SubnetIds":["subnet-04e1d4297c776f5eb"]}' \
 --tags 'Project=EMR-Practice' 'for-use-with-amazon-emr-managed-policies=true' \
 --applications Name=HBase Name=Hadoop Name=Hive Name=Livy Name=Spark \
 --configurations '[{"Classification":"spark-hive-site","Properties":{"hive.metastore.client.factory.class":"com.amazonaws.glue.catalog.metastore.AWSGlueDataCatalogHiveClientFactory"}}]' \
 --instance-groups '[{"InstanceCount":1,"InstanceGroupType":"CORE","Name":"Core","InstanceType":"r6g.xlarge"},{"InstanceCount":1,"InstanceGroupType":"MASTER","Name":"Primary","InstanceType":"r6g.xlarge"},{"InstanceCount":1,"InstanceGroupType":"TASK","Name":"Task","InstanceType":"r6g.xlarge"}]' \
 --scale-down-behavior "TERMINATE_AT_TASK_COMPLETION" \
Why we w --ebs-root-volume-size "30" \

Why we w --region "us-east-1"~ $ 
 
 
📌 Why we executed It ?
To automate cluster creation and avoid manually typing a long AWS CLI command repeatedly.

🔸script creation
🔸Infrastructure automation preparation
