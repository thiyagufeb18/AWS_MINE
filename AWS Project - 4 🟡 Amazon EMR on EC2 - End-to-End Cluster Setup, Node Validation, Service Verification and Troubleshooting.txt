AWS Project - 4 🟡 Amazon EMR on EC2 - Implementation Steps
#############################################################

📌 Project Objective
Deploy an Amazon EMR Cluster using the EMR on EC2 deployment model to perform distributed data processing using Hadoop, Spark, Hive, HBase, and Livy.

🟢 The environment should allow administrators to:
---------------------------------------------------
✔ Connect to the Primary Node using SSH.
✔ Validate Hadoop ecosystem services.
✔ Validate HDFS and YARN services.
✔ Validate Spark, Hive, HBase, and Livy.
✔ Identify Primary, Core, and Task Nodes.
✔ Create Hive databases.
✔ Perform HDFS read/write operations.
✔ Execute Spark applications.
✔ Verify service placement across nodes.
✔ Verify cluster health.
✔ Verify storage allocation.
✔Terminate the cluster after testing.

Task 21 - Troubleshooting and Lessons Learned ✅
----------------------------------------------

Issue: Unable to connect through SSH.
Root Cause:  Public IP address changed and Security Group contained the old source IP.
Resolution: Updated SSH inbound rule with current public IP.

Issue: Unable to access EMR application UIs directly. 
Root Cause: EMR Block Public Access enabled.
Resolution: Used SSH-based validation and identified UI service ports.

Issue: Expected Hadoop daemon names not displayed through jps.
Observation: 
Output displayed:
Main
Jps

Resolution:
Used: systemctl status  and  ps -ef | egrep 'namenode|resourcemanager|datanode|nodemanager'
for accurate service validation.
